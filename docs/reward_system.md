# 内容质量评分体系

> 目标只有一句：**奖励内容质量本身，而不是求助、热度、刷屏或重复顶帖。**

绝大多数「按数据发奖」的尝试会滑向同一个失败模式——谁的帖子回复多、谁活跃、谁来得早，就奖谁。这会把奖励变成对既有流量的再分配，并系统性冷落真正在写字的人。本体系的设计全部围绕绕开这个失败模式。

---

## 1. 三个信号的定义

先把「什么样的行为算创作」定义清楚，否则后续一切权重都建在沙子上。

判据只看 **楼主自己的回复**（`p[p.author_id == au]`），不掺入他人互动：

| 信号 | 判据 | 含义 |
| --- | --- | --- |
| `self_bump` | 去掉空白后长度 **≤ 5 字符** | 顶帖 / 纯灌水 |
| `self_long` | 长度 **≥ 15 字符** | 有实质内容的续写 |
| `self_deep` | 长度 **≥ 30 字符** | 深度续写 |
| **创作层** `self_long_uniq` | 按主题取 `nunique()` | 楼主贡献了**几段不同的**长文 |
| **深度** `self_deep_uniq` | 按主题取 `nunique()` | 其中达到深度阈值的段落数 |

关键在 **`nunique()` 而不是 `count()`**：同一段话反复发不算创作，只有不同内容才计数。

### 为什么把「顶帖」单独拧出来

短顶帖占楼主自我回复的 **36.5%**，体量最大。但它的判别力只有 **AUC 0.5304**——基本等同抛硬币。

把它混进正向信号里，等于往信号里注入噪声：

| 处理方式 | 内容质量判别 AUC | 作者身份偏差 |
| --- | --- | --- |
| 不区分自我回复类型 | 0.7822 | 0.2727 |
| **按类型区分，顶帖单独作负向** | **0.8041** | **0.2131** |

所以顶帖不但不进正向项，反而带**负权重**。这一步同时提升了判别力、降低了「谁发的」对结果的影响。

## 2. 事实效用分

主分为各类互动与创作强度的线性组合（权重常量定义于评分模块）：

| 项 | 权重 | 方向 |
| --- | --- | --- |
| 回复数 | 0.60 | 正 |
| 评论数 | 0.30 | 正 |
| 讨论广度（参与人数） | 0.30 | 正 |
| 参与天数 | 0.18 | 正 |
| **创作层**（原创长文段数） | **1.15** | 正（最高） |
| **深度**（深度段数） | 0.80 | 正 |
| 顶帖次数 | −0.60 | **负** |
| 纯长度 | 0.0 | 不计 |

三点刻意的设计：

- **创作层的权重高于任何互动项。** 互动可以被时间和流量放大，创作不能。
- **纯长度权重为 0。** 长文不等于好文，用长度当质量是懒惰的代理变量；长度只作为**分段阈值**参与，不作为打分项。
- 所有计数项进入前取 `log1p`，压制头部极值。

### 媒体

媒体在评分层单独以 `W_IMG · log1p(图片数)` 加入（`W_IMG = 0.3`）。取 0.3 是在实测曲线上取的拐点：使精华内容进入前 5% 的比例由 **79.0% 提升到 82.7%**，而同时高创作内容进入前 5% 的比例仅由 93.4% 微降到 92.8%——用 0.6 个百分点的代价换 3.7 个百分点。

只使用平台自带的媒体计数，**不依赖任何需要额外跑模型才能得到的多模态分数**：缺失特征按 0 处理，而不是编一个出来。

## 3. 完整性闸门

质量分回答「值多少」，闸门回答「够不够格被发放」。两者**分开**，不做乘法混合——否则一次刷屏会把一个高创作帖子整体清零。

```
integrity = 1 − ( DUP_W · d + SELF_SHARE_W · s + LOW_EFFORT_W · le )

d  = min(1, log1p(重复次数) / log1p(DUP_SAT))，重复次数 > 1 时生效
s  = 楼主自我回复占比
le = 低努力标记
```

| 常量 | 值 | 说明 |
| --- | --- | --- |
| `DUP_W` | 0.50 | 重复项权重 |
| `SELF_SHARE_W` | 0.30 | 自我回复占比权重 |
| `LOW_EFFORT_W` | 0.30 | 低努力权重 |
| `DUP_SAT` | 8.0 | 重复次数饱和点 |
| `INTEGRITY_GATE` | 0.60 | 低于此不进入发放池 |

**低努力门采用 AND 口径（短正文 **且** 短标题 **且** 无媒体）。** 这一点容易写错：若改成 OR，会误伤大量只有标题短、但正文与配图都完整的正常帖——实测中该口径曾一次性误杀多篇优质置顶内容。

**刷屏硬拦截**独立于闸门：当顶帖占比 > 0.8 且原创长文段数 ≤ 2 时，直接判定为顶帖刷屏，不进入排名。该规则在实测中命中 21 例、**0 例误伤**（全部命中对象都没有得分）。

## 4. 分档与积分

档位边界是**队列内分位点**，不是绝对分数。理由：分位制下奖励总额自动跟随队列规模，既不需要周期性重调预算，也不会因为某个季度发帖量暴涨而超支。

按队列规模自动选择粒度——小队列分太细会人人有奖，失去区分度：

| 队列规模 | 边界（分位） | 各档积分 | 获奖比例 |
| --- | --- | --- | --- |
| n ≥ 250 | 0.80 / 0.90 / 0.96 / 0.99 | 10 / 30 / 60 / 100 | 20% |
| 100 ≤ n < 250 | 0.70 / 0.85 / 0.95 | 5 / 20 / 60 | 30% |
| 30 ≤ n < 100 | 0.70 / 0.85 | 10 / 30 | 30% |

**百分位只在可排名子集内计算。** 被闸门拦截的帖子不参与分位计算，否则获奖比例会被无效数据稀释。

> **切点位置与分值梯度的取舍（实测）。** 把切点上移（收紧到前 2%）能把「每千分捕获的有效创作数」提高数倍，但**在同等发放总额下几乎无收益**（最优与现状之比仅 1.09），且会牺牲大量边缘合格帖 —— 因此切点保持较宽覆盖。
>
> 真正有效的杠杆是**分值梯度**。切点固定、仅把低档积分从 10/30/60 收紧到 5/20/60：历史每千分捕获从 2.19 升到 **2.86（+31%）**，积分总额下降 23%，而有效创作捕获量 577/579 **不变**。即低分区的开销被削掉，高档回报一分未减。

## 5. 建模

除主分之外，另有一个成对偏好模型用于辅助判断，使用 Ridge 回归（`RIDGE_ALPHA = 5.0`）。

**作者的历史水平只作为特征，不进入最终奖励排序。** 这条是有证据的：把这层身份特征全部移除后，与保留时的排序结果对比——

- Spearman **0.99783**
- 前 10 名 **10/10** 相同
- 前 20 名 **20/20** 相同

即该层的全部实质影响都来自身份项本身，而对最终排序没有贡献。而身份项在奖励语境下是有害的：它会让新人永远排不过老人。因此**不采用**。

对待作者历史的正确定位是：作为**先验参与打分**（新人冷启动时回退到全局均值）没有问题，但**不能进入奖励排序**。

## 6. 验证

| 指标 | 结果 | 说明 |
| --- | --- | --- |
| 样本外内容质量判别 AUC | **0.9595** | 在时间切分的样本外区间上评估 |
| 随机标签负对照 | 0.5207 | 打乱标签后回到随机水平，排除了流程泄漏 |
| 未训练下界 | 0.4739 | 模型必须显著高于这条线才有意义 |
| 作者身份消融 | Spearman 0.99783，前 10 名 10/10 | 移除作者特征后排序几乎不变 |

### 残差构造（L2）的解释力

以下三个数字是在**本仓库的 `build_residual.py` 上重新实测**的（99,392 篇帖，时间切分
train 59,672 / val 17,381 / test 22,306），不是从别处抄的：

| 指标 | 结果 | 说明 |
| --- | --- | --- |
| Ridge R²（train / val / test） | 0.3976 / 0.3968 / 0.3699 | 三者接近，无过拟合迹象 |
| 仅作者身份的解释力（全样本均值，含泄漏） | 0.6041 | 混杂的信息上限 |
| 仅作者身份的解释力（as-of 先验，无泄漏） | 0.1473 | 真实可部署的水平 |

**这两个「仅作者」的数字差得很远，不是矛盾，是口径不同**：全样本均值用了未来信息，
所以它是含泄漏的上界；as-of 先验只用该帖之前的历史，才是部署时真正能拿到的。
README 与本文档早期版本里出现过 0.4475 / 0.4402 / 0.6488 —— 那些来自另一套历史口径，
发布副本上复现不出，故以本表为准。

评测协议的三条纪律：

1. **按时间切分，不随机切分。** 随机切分会把同一时期的帖子分到训练与测试两侧，造成乐观偏差。
2. **必设随机标签负对照。** 若打乱标签后指标仍然偏高，说明存在数据泄漏，结论作废。
3. **必报未训练下界。** 只报「比 baseline 高」而不报绝对水平，无法判断模型是否真的有信号。

## 7. 已知边界

1. **相关不是因果。** 本体系度量的是「什么样的帖子更可能被公认为优质」，**不证明**「发什么样的帖子能导致被公认为优质」。任何把分数当作因果关系解读的用法都超出其证据范围。
2. **只在单一论坛验证。** 全部权重与阈值来自一个吧的数据，跨吧通用性尚未被证明。
3. **偏好模型的幅度信息有损。** 成对偏好训练会丢掉绝对幅度，因此其分数只宜用于相对比较，不宜直接结算。
4. **信号偏向可见行为。** 体系只能看到平台暴露的计数与文本；「写得好但无人回复」的内容无法被充分识别。
